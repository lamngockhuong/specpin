---
title: グラフビュー
description: ステータスフローと画面遷移の図を作成し、フルページのグラフビューで閲覧する。
---

`.specs/`内の2つの任意ファイルは、専用のフルページ**グラフビュー**で図として描画されます：**ステータスフロー**グラフ（オブジェクトのステータスがどのように状態間を移動するか）と**画面遷移**グラフ（どの画面がどの画面に、どのアクションで遷移するか）です。どちらもspecと同じく`.specs/`内で手作業により作成します。

:::note
グラフビューは`.specs/flows.json`と`.specs/screens.json`のデータを描画します。JSONとして直接作成してください（`.specs/`作成の一般的なモデルは[Spec format](/ja/sidecar/spec-format/)を、`flows.json`/`screens.json`の正確なフィールド仕様は[GitHubのschema-reference.md](https://github.com/lamngockhuong/specpin/blob/main/docs/schema-reference.md#flowsconfig-specsflowsjson)を参照してください）。あるいは、グラフビュー上でノードや遷移を直接編集することもできます。JSONの手動編集は一切不要です - 詳しくは下記の[ブラウザ上でflows/screensを編集する](#ブラウザ上でflowsscreensを編集する)を参照してください。`screens.json`の遷移は、自動記録をオンにしてその観測結果を承認することでも追加できます - 詳しくは[画面遷移の自動記録](#画面遷移の自動記録)を参照してください。
:::

## ステータスフローグラフを作成する

`.specs/flows.json`を作成し、オブジェクトのライフサイクルを記述します（例：「Deal」が営業パイプラインをどう移動するか）：

```json
{
  "version": "1.0",
  "flows": [
    {
      "id": "deal-status",
      "object": { "en": "Deal" },
      "states": [
        { "id": "draft", "label": { "en": "Draft" }, "kind": "initial" },
        { "id": "negotiation", "label": { "en": "Negotiation" } },
        { "id": "won", "label": { "en": "Won" }, "kind": "terminal", "specId": "deal-stage" },
        { "id": "lost", "label": { "en": "Lost" }, "kind": "terminal", "specId": "deal-stage" }
      ],
      "transitions": [
        {
          "id": "start-negotiation",
          "from": "draft",
          "to": "negotiation",
          "trigger": { "en": "Start negotiation" },
          "specId": "deal-submit"
        }
      ]
    }
  ]
}
```

1つのファイルに複数の独立したフロー（オブジェクトの種類ごとに1つ）を持たせられます。各stateの`kind`（`initial` / `normal` / `terminal`）は描画のされ方を左右します。stateやtransitionの任意の`specId`はピン留め済みのspecへ逆リンクするので、グラフ内でクリックすると実際の要素にジャンプできます（下記の[Click-to-highlight](#click-to-highlight)を参照）。

## 画面遷移グラフを作成する

`.specs/screens.json`を作成し、アプリのナビゲーションを記述します：

```json
{
  "version": "1.0",
  "screens": [
    { "id": "login", "name": { "en": "Login" }, "urlGlob": "/login" },
    { "id": "dashboard", "name": { "en": "Dashboard" }, "urlGlob": "/" }
  ],
  "transitions": [
    {
      "id": "login-to-dashboard",
      "from": "login",
      "to": "dashboard",
      "trigger": { "en": "Sign in" },
      "specId": "login-submit-btn"
    }
  ]
}
```

各画面の`urlGlob`は、specのページスコープと同じglob構文（`*`は1つのパスセグメントに、`**`は複数セグメントにマッチ）を使って、実際のUI上でその画面を識別します。

## グラフビューを開く

popupまたはサイドパネルのヘッダーにある**⋯ More actions**メニューから**Open graph view**をクリックします。新しいブラウザタブで開きます。接続中のプロジェクトにステータスフローと画面遷移の両方のグラフが設定されている場合、キャンバス上部にデータセット選択が表示され切り替えられます。1つのページを複数のプロジェクトが配信している場合は、プロジェクト選択も表示されます。

## グラフを閲覧する

- **Graph / Table 切り替え**: 視覚的な図と、同じノード・エッジのプレーンなソート可能テーブルを切り替えます。
- **カテゴリフィルタ**: タブごとにノードをグループ化し件数を表示します（ステータスフローグラフはオブジェクトの種類でグループ化、画面グラフは各画面`urlGlob`の最初のパスセグメントでグループ化）。タブを選ぶとそのカテゴリ以外は非表示になります。
- **検索**: 入力するとマッチするノードのラベルがリアルタイムでハイライトされます。検索はハイライトするだけで何も非表示にしません（先にカテゴリフィルタで絞り込んでから組み合わせると便利です）。
- **フォーカス**: ノードをクリックすると、そのノードと直接つながるノード・エッジ以外が暗くなります。もう一度クリックするか、空白部分をクリックするとフォーカスを解除します。
- **パン・ズーム**: キャンバスをドラッグしてパン、スクロールでズームします。

これらは自由に組み合わせられるので、1つのカテゴリに絞り、その中で検索し、特定のノードにフォーカスする、といったことを同時に行えます。数百ノードのグラフで役立ちます。

## Click-to-highlight

`specId`を持つノードまたはエッジをクリックすると、グラフビューを開いた元のタブへジャンプします。そのspecが現在そのタブでマッチしていれば、要素がスクロールして表示され点滅します。これはディープリンクやキーボードのサイクルショートカットと同じハイライト処理です。

そのタブでspecがマッチしていない場合（違うページにいる、または要素が存在しない場合）、何も起きない代わりに、そのspecが属する画面・ページ名を示すヒントが表示されます。`specId`を持たないノード・エッジ（「Won」のような純粋なステータスや、単一の起動要素を持たないナビゲーションなど）は通常どおり描画されますが、ジャンプ先はありません。

:::tip
実際のUI要素がstateやtransitionを表している場合（ステータスバッジ、送信ボタンなど）は`specId`を設定し、グラフと実際のページを結び付けておきましょう。専用の要素を持たない純粋に概念的なノード（要素のないterminalステータスなど）は`specId`を未設定のままで問題ありません。
:::

## 画面遷移の自動記録

`screens.json`の各エントリを手動で書く代わりに、自分自身のナビゲーションを監視し、承認すべき新しい画面遷移を提案するオプトインのレコーダーをオンにすることもできます。

:::caution
デフォルトはオフです。オンにする前に、何が記録されるかを確認してください。
:::

**オンにする。** 拡張機能のOptionsページ -> **自動記録**を開き、そのカードのプライバシーに関する記述を読んでから、**この端末でナビゲーション遷移を記録する**にチェックを入れます。チェックボックスのすぐ横に点滅する**ナビゲーションを記録中**インジケーターが表示され、オフスイッチはワンクリックの距離にあります。グラフビューにも同じインジケーターがバナーとして表示され、独自の**オフにする**と**記録をすべてクリア**（選択中のプロジェクト分）のアクションがあります。

**記録される内容。** 各ページの一般化された画面パスのみ（例: `/orders/**`。`/orders/1938`のような具体的なパスは記録されません）と、そのような2つの画面間のナビゲーションです。記録されないもの: クエリ文字列、ハッシュ、ページの内容。idらしいパスセグメントは保存前に`**`に一般化されますが、承認する前に各遷移を確認してください。記録した時点では何も`.specs/`には届きません - 観測した遷移はそれぞれ、プロジェクトごとのローカルなドラフトバッファ（上限あり、`storage.local`、アップロードされない）に入り、承認待ちの提案のままです。

**レビューして承認する。** 記録がオンの状態でサイトを閲覧し、グラフビューの**Screens**データセットを開きます。新しく観測された画面・遷移は、確定済みのものに混じって、破線の半透明な「ゴースト」ノード・エッジとして描画されます。ゴーストエッジをクリックすると**承認**（`"source": "auto-captured"`として`screens.json`にマージし、同じidを持つ既存のmanual/importedエントリを上書きすることはありません）または**破棄**（どちらの場合も`.specs/`への書き込みなしで削除）できます。バナーは、記録はオンだがまだ何も記録されていない場合や、プロジェクトのドラフトバッファが満杯になった場合にも知らせてくれます。

:::note
プライバシーの流れ全体: オプトイン、デフォルトは**オフ** -> 一般化されたURL形状のみを導出（クエリ・ハッシュは破棄し、idらしいパスセグメントは`**`に一般化） -> 端末ごとのローカルなドラフトバッファに保持し、自動では書き込まれない -> 何かが`.specs/`に届く前に、必ずあなたの明示的な承認が必要。記録したデータがあなたのマシンから出ることはありません。
:::

## ブラウザ上でflows/screensを編集する

グラフビューは眺めるだけの図ではありません - **Edit mode**をオンにすると、キャンバス上で直接ノードやtransitionを追加・編集・削除でき、JSONの手動編集は一切不要です。

**オンにする。** グラフビューのコントロールバーで**Edit mode**をクリックします。ツールバー（**Add node**、**Add edge**、**Delete selected**、**Undo**、**Save**）が表示され、ノードまたはエッジをクリックすると、以降はナビゲーションやclick-to-highlightの代わりに編集対象として選択されるようになります。

**ノードを追加する。** **Add node**をクリックし、横の form に入力します：ロケールごとの名前/ラベル（locale ごとに行を追加）、`urlGlob`（screens）または`kind`（flowsのstate: initial/normal/terminal）、そしてプロジェクトの既知のspecから選ぶ任意のリンク先spec。**Create**でドラフトに追加されます。status-flowデータセットでは、新しいノードは現在アクティブなflowに属します - プロジェクトにまだflowがなければ、先にflowコントロールで1つ作成してください。

**ノードやエッジを編集する。** 既存のものをクリックすると、同じ横の form が値を入力済みの状態で開きます。有効なフィールド変更はすぐにメモリ上のドラフトへ反映されます。**Save**は依然としてドラフトを`.specs/`へ永続化する操作です。code-importやauto-captureから来たtransitionはここでは読み取り専用として表示されます - それぞれ専用のフロー（importの再実行、またはghost edgeの承認/破棄）で変更してください。

**エッジを追加する。** 2つのノードを順番（from、次にto）にクリックして選択し、**Add edge**を押すとtriggerラベルと任意のguard/role/リンク先specを入力する form が開きます。

**削除する。** ノードまたはエッジを1つだけ選択し、**Delete selected**を押します。import/auto-capture由来のエッジがまだ参照しているノードは削除を拒否されます - 先にそのエッジを解決してください（手動で追加したエッジはノードと一緒にカスケード削除されます）。specshotのspec sheetがまだ参照しているscreenを削除することはここでは許可されます。そのチェックは代わりにSave時に行われます（次項）。

**Undo。** **Undo**は直近の1件だけを取り消します - 履歴全体ではなく1ステップだけです。次の編集をする前に、うっかりミスの直後に使ってください。

**Saveと、孤立するshotのチェック。** **Save**はドラフト全体を永続化します：上記のauto-captureの承認フローと同じprovenance保存方式で検証・マージされます - あなたの編集が他のソースのエントリを上書きすることはなく、その逆もありません。このセッションで、まだspec sheetが参照しているscreenを削除していた場合、Saveは先に確認を求め、何件のshotが孤立するかを示します（あるいは確認できない場合は一般的な注意喚起を示します） - Cancelして見直すか、そのまま保存を続けられます。

**未保存の変更を残したまま離れる。** ドラフトに未保存の変更がある状態でEdit modeをオフにする、プロジェクトを切り替える、flows/screensのデータセットを切り替える、といった操作は、先に保存するか破棄するか確認を求めます。変更のないきれいなドラフトでは確認は表示されません。未保存の編集があるままタブを閉じる・再読み込みする場合も、ブラウザ自体の離脱警告が表示されます。

:::note
このエディタが書き込むのは`.specs/flows.json`と`.specs/screens.json`だけで、ここにある他のどの書き込み処理とも同じ「読み取り→マージ→検証→書き込み」の経路を使います - 新しいスキーマも、新しい書き込み経路も追加していません。
:::
